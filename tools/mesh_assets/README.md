# Full-quality prebuilt aircraft assets

These tools move the existing production aircraft bake out of the player's first
launch. They do not change the meshing algorithm, render shaders, materials,
ambient occlusion, model dimensions, moving hulls, rigid parts or animation.
Every release bundle contains the exterior and cockpit of all 15 aircraft,
including the research fleet: 30 independently identified meshes.

The portable files contain the exact production float32 and uint32 payloads.
There is no quantization, decimation, normal repacking, animation flattening or
other quality reduction in this export path. The production builder's existing
sampling and simplification remain unchanged. ZIP DEFLATE is lossless transport
compression; extraction restores each mesh byte for byte.

## Build and bake

Requires CMake, a C++17 compiler, Python 3.9+ and an existing Linux EGL/OpenGL 3.3
implementation with at least 22 fragment texture units. The exporter dynamically
loads `libEGL.so.1`; it needs neither EGL development headers nor an X server.
Use a known full-quality canonical producer driver. A Mesa software renderer is
supported, but the complete cold bake can be slow and memory-intensive. Keep the
build and bake serial on memory-limited machines. No dependencies are installed
by these scripts.

From the repository root:

```sh
cmake -S . -B build-mesh -DCMAKE_BUILD_TYPE=Release
cmake --build build-mesh --target aircraft_mesh_export --parallel 1
python3 tools/mesh_assets/test_mesh_assets.py
# The destination must not already exist. This always performs 30 fresh bakes.
build-mesh/aircraft_mesh_export out/aircraft-raw
python3 tools/mesh_assets/mesh_assets.py bundle \
  --input out/aircraft-raw \
  --source-manifest build-mesh/gen/aircraft_geometry_source.json \
  --output out/SolaceExpress-aircraft.zip
```

For a software-Mesa producer, set `LIBGL_ALWAYS_SOFTWARE=1` and, if appropriate,
`GALLIUM_DRIVER=llvmpipe` for the export command. Record the actual GL vendor,
renderer and version in the emitted report; do not claim equivalent native GPU
performance from a software-renderer measurement.

The source manifest is generated as a build dependency. It records SHA256 for
CPU geometry inputs, all raw GLSL inputs, and the exporter source.
The geometry digest includes the exporter state-setup contract as well as the CPU
builder sources; raw GLSL also contributes to the complete build digest. The binary
embeds both the CPU/producer geometry digest and the complete build digest.
Packaging rehashes the current checkout and rejects stale source files, stale
exporter binaries and mixed source bundles. Do not edit the manifest to make an
old binary pass. Rebuild, then rebake into a new directory.

The default source revision in the release manifest is `git rev-parse HEAD`.
For a source archive without `.git`, explicitly pass `--source-revision` with its
release identifier. This label is descriptive: the byte hashes and compiled
source digests establish actual identity, including uncommitted source changes.
The default source root is the repository containing this tool; use
`--source-root PATH` when validating another exact checkout.

For a diagnostic single-body bake, create an empty disposable directory and run
`aircraft_mesh_export --bake-one MODEL SLOT DIRECTORY` (`MODEL` 0–14, `SLOT` 0 for
exterior or 1 for cockpit). This emits a mesh and a temporary worker receipt;
it cannot produce a complete release report and the bundler refuses it. Do not
combine independent diagnostic results or old caches to manufacture a release.

## Verify and stage a release

```sh
python3 tools/mesh_assets/mesh_assets.py validate \
  --input out/aircraft-raw \
  --source-manifest build-mesh/gen/aircraft_geometry_source.json
python3 tools/mesh_assets/mesh_assets.py extract \
  --input out/SolaceExpress-aircraft.zip \
  --source-manifest build-mesh/gen/aircraft_geometry_source.json \
  --output dist/SolaceExpress/aircraft
```

`extract` refuses an existing destination. Stage a new release directory instead
of overwriting the user's installation or cache. Include the resulting
`aircraft/` directory beside `SolaceExpress.exe` in the final game ZIP. The native
development default is `assets/aircraft/`; the Windows game resolves `aircraft/`
relative to its executable, independently of its launch working directory.
Never package `%LOCALAPPDATA%/SolaceExpress`, a `shadercache` directory, `*.bin`
program binaries, driver rejection markers, or arbitrary files from an old
review cache.

The standalone ZIP's root is `aircraft/`. It contains only:

- 30 `aircraft_<model>_<view>_<identity>.mesh` files
- `bake-report.json`, produced only after all 30 fresh strict bakes succeed
- `manifest.json`, independently checked and generated by the bundler

The manifest includes model IDs/names, view, format/algorithm/profile versions,
source revision and per-input hashes, per-mesh identities and SHA256, file and
payload sizes, vertex/index/triangle counts, fine-patch split, moving-hull counts,
and every rigid part's stable type. It records producer GL provenance without
including any driver executable code or shader binary.

Archive entry order, timestamps, permissions, JSON key ordering and compression
settings are fixed. Repackaging identical exported bytes with the same source
revision and Python/zlib implementation produces the same ZIP bytes. Independent
GPU bakes on different drivers are not promised to produce identical floats; the
canonical exported bytes are the release's fixed geometry. The game validates
its compatible source/model/view identity before using them on another driver.

## Failure and quality rules

- The exporter bypasses both packaged assets and the legacy local mesh cache.
  It calls the existing production baker directly with canonical packed model
  parameters and the original complete moving-state sweep. The canonical propeller/
  fan phase, visual running state and per-engine health match the actual first
  prewarm frame: `(3.f + 1.f/60.f) * 250.f`, running blur 1, authored blade count,
  healthy existing engines. This preserves the original startup fan AO exactly;
  the source-contract test flags changes to these copied startup rules.
- `AF_ALL`, `CLIPDBG` and `NV_SAFE_GEAR` environment overrides are refused. The
  strict production export path refuses a shared/failed/reduced-gear builder.
  A driver compiler failure cannot silently publish a gear-less mesh.
- Meshes are captured before GPU upload. The exporter does not initialize the
  world, menu, career, saves, materials or shader-binary cache. One fresh subprocess
  and EGL context is used per model/view, serially, so compiled shader programs
  cannot accumulate across the fleet. The coordinator verifies each worker's
  source/model/view/full-quality/GL receipt and decodes its output before
  removing that temporary receipt.
- Individual files are atomically published by the production writer. The
  exporter uses a private sibling staging directory and renames it only after
  all 30 bakes and the complete report succeed. Failure never produces the final
  output directory. Interruption can leave a hidden `.baking.*` directory, which
  is not an accepted release input without a complete producer report.
- The bundler checks lengths before mapping payloads, every header identity and
  SHA256, finite positions/normals/hulls, normal/AO bounds, index ranges, part
  types/uniqueness, the exact roster and complete 30-file set. Unexpected files,
  links, malformed archives, traversal paths and duplicate archive names fail.
- ZIP publication is atomic. The ZIP itself is extracted and revalidated before
  it replaces any existing output. An invalid/incomplete bake cannot replace a
  previously valid release ZIP. Extraction validates in a private temporary
  directory before publishing a new complete destination.
- There is intentionally no legacy-cache conversion/import command. A matching
  old filename or source-looking stamp cannot establish that its payload was
  baked without `NV_SAFE_GEAR` or other fallback changes.

A missing, corrupt, incompatible or individually stale shipped mesh is handled
by the renderer's existing local-cache/procedural fallback for that aircraft.
The package is read-only at runtime. Driver-specific shader compilation remains
necessary on first launch; shipping meshes eliminates expensive geometry bakes,
not all first-run graphics work.

## Tests and acceptance

The small Python suite uses synthetic lossless fixtures and requires no GL. It
covers exact archive round trips, deterministic packaging, source/build changes,
header and payload corruption, bounds, duplicate parts, incomplete rosters,
reduced-quality flags, manifest disagreement, archive safety, and failed atomic
publication. The C++ asset-format tests exercise the actual runtime decoder.

Before releasing actual art, additionally run the native integration checks:

1. Complete a fresh canonical 30-body bake, validate and bundle it.
2. Compare exported payloads to independent production bakes at the same source
   and producer; require byte-equivalent vertices, normals/material/AO, indices,
   fine split, moving hulls and rigid parts.
3. Start with an empty user cache and a complete shipped bundle. Confirm all 30
   mesh hits and zero procedural mesh bakes. Measure the actual startup phase.
4. Remove or corrupt one shipped mesh in a disposable copy. Confirm only that
   body falls back, without changing/deleting the shipped file or valid siblings.
5. Exercise gear/control/flap/steering poses, cockpit controls, research animation,
   Atlas fans, damage and breakup on the intended Windows GPU. Portable-file unit
   tests and Mesa captures alone do not establish Windows driver frame rate or
   complete visual acceptance.

Do not publish a speedup number until measured against the same-source baseline
on the same machine with comparable cold/warm shader and local-cache state.
